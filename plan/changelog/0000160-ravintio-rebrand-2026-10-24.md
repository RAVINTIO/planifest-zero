**Feature:** ravintio-rebrand
**Version:** 1.0.0

## What changed

Planifest Zero is now RAVINTIO Zero, part of the RAVINTIO ecosystem beside RAVINTIO Framework, Accept, and Assess. Every path, name, and message changed, so 1.0.0 is a breaking release for installed consumers. A migration upgrades them.

- req-001: the pack folder is `ravintio-zero/` and the overrides folder is `ravintio-overrides/`. The 12 skills are `ravintio-*`. The workflow file is `ravintio.yml`, and the refresh script is `refresh-ravintio-zero-dir.ps1`. Test file names, `product.yml`, and `component.yml` follow.
- req-002: hooks, setup, scripts, and CI detect and write the new names, including the `.ravintio-*` marker files. Setup stops and names the migration helper when it finds an old pack or overrides folder. It also removes the two old marker files.
- req-003: every `PLANIFEST_*` variable is now `RAVINTIO_*`. The roadmap runner still reads `PLANIFEST_ROADMAP_MODEL` and `PLANIFEST_ROADMAP_MAX_TURNS` in 1.x, and the new name wins. OTEL labels are `ravintio.roadmap` and `ravintio.step`.
- req-004: prose writes the brand as RAVINTIO in block capitals. GitHub links point at the `ravintio` org, and sibling repo names stay as they are.
- req-005: migration 0004 and its Bash and PowerShell helpers upgrade a consumer. They move the overrides folder and the workflow, rewrite the pack's own workflow variables, and remove the old markers. They move the old pack to `.ravintio-backup/` and never delete it. A migration can now declare `Applies when:`. The orchestrator and the migrator skip it while the condition is false.
- req-006: a brand guard test fails on any tracked path or line outside history that names the old brand, unless a narrow allowlist entry matches. A stale entry also fails.

The em dash guard still accepts the old `planifest-em-dash-allow` sentinel in 1.x.

## Why

The product joins the RAVINTIO ecosystem. Every name a user sees or types had to carry the new brand, and installed consumers needed a safe upgrade.

Decisions:

- ADR-001: the rename map. Prose uses RAVINTIO in capitals, and identifiers use lowercase `ravintio`. History folders stay as written.
- ADR-002: two roadmap variables and the em dash sentinel keep their old names as fallbacks through 1.x.
- ADR-003: consumers upgrade through migration 0004. The helper backs up the old pack instead of deleting it.
- ADR-004: a brand guard test with a path and line allowlist.

## Deviations

- One scripted pass did the mechanical rename for REQ-001 to REQ-004, so those requirements had no TDD track. P3 added their tests.
- The bulk rename changed four split old folder names in 0000031 and 0000037 tests. P3 restored them.
- REQ-005 found that this repo would run pending migration 0004 against itself. The `Applies when:` precondition fixes that, and REQ-005 and ADR-003 changed to match.
- REQ-002 said the em dash guard covers the overrides folder. It never did, before or after the rename, so the requirement now matches the code.
- The first security review found a High: the PowerShell helper's recursive delete could follow a nested junction on Windows PowerShell 5.1. P3 replaced the delete with a move to `.ravintio-backup/`.
- macOS ships Bash 3.2, which silently drops lines from `done < <(grep ...)` in long loops. The brand guard now avoids that. Backlog 0000161 covers four older suites.
- P3 hit the five-cycle limit. The human approved a sixth cycle, which fixed two guard tests that needed an entry for each other.
- `pwsh` is not installed locally, so CI ran the PowerShell suites. PR #25 opened as a draft during P3.
- The release is far over the 8-point budget. It cannot split, because a half-renamed pack fails its own tests.
