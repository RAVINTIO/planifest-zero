# Changelog (0000252-chart-rules, 28 Oct 2026)

**Feature:** Chart rules
**Version:** 0.40.0
**PR:** #70

## What changed

- `roadmap-standards.md` gains a guard check in I-A Chart. Chart checks each entry for a widening of `merge-guard`, `gate-write`, `ratchet-check`, or another fail-closed hook. It names the guard and the new forms, and needs a separate approval for each widening (entry 0000223).
- `roadmap-standards.md` gains a Chart-time confirmations subsection. Chart lists each confirmation that a step's skills ask for, and records the exact command as a `Confirmation:` row in `## Decisions` or plans a human stop. I-C Run runs a matching row with no stop (entry 0000225).
- `initiative.template.md` gains a `Confirmation:` row form in `## Decisions` and a `## P1 skips` section between `## Criteria` and `## Steps` (entries 0000225 and 0000234).
- `roadmap-standards.md` gains a Chart-time P1 skips subsection. Chart may mark `yes` only for a chore with exact tasks or a change with no code. I-C Run stops a step with no `yes` row with `I-C Run: Blocked:`, and the build log names the chart row when a step skips P1.
- The Phase Skip Protocol reference states the same stop for a step session.
- `ravintio-initiative/SKILL.md` holds the guard check and the step confirmation in its Chart section.
- Three tests: `test-0000252-req-001-guard-widening-rule.sh`, `test-0000252-req-002-step-confirmation-rule.sh`, and `test-0000252-req-003-p1-skip-record.sh`.
- `docs/architecture-overview.md` and `ravintio-zero/component.yml` describe the change.

## Why

In initiative 0000195, a first chart draft widened a fail-closed guard, a chore step stopped for a confirmation that chart never listed, and three steps skipped P1 with no chart row that allowed it. Each gap now has a chart rule, so the human decides each one at chart.
