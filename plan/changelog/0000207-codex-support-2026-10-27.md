# Changelog (0000207-codex-support, 27 Oct 2026)

**Feature:** Codex support
**Version:** 0.29.0
**PR:** #50

## What changed

- `setup.sh` and `setup.ps1` accept `codex` beside `claude-code`. The new `setup/codex.sh` and `setup/codex.ps1` hold the Codex config.
- Setup for `codex` writes an `AGENTS.md` boot file from the new `codex-boot.md` template and installs the skills in `.agents/skills/`.
- Setup wires `merge-guard` as a `PreToolUse` hook for `Bash` in `.codex/hooks.json`. A rerun keeps one entry and every other entry. Invalid JSON stops setup with one fixed line.
- Setup prints the active hooks, the fallback hooks, and the `/hooks` review step. `AGENTS.md` states each fallback rule as an instruction.
- The refresh-setup skill, the getting-started guide, the README, and the architecture overview name the `codex` target.
- New Bash and PowerShell suites install for `codex` and check the files. The tool-check suites now treat `windsurf` as the unknown tool.

## Why

A team that uses Codex could not install the pipeline. The human on the loop chose Codex as the first extra harness (backlog entry 0000175).

## Deviations

- Only `merge-guard` is wired. The Codex docs don't state the `apply_patch` input or the prompt hook context, so the other hooks stay instructions (ADR-002).
- No Codex program was available. The `hooks.json` shape and the exit 2 contract come from the Codex docs and were not run in Codex.
- The installed copies under `.claude/skills/` keep the old skills until step 13 of initiative 0000195 reruns setup. `test-0000151-req-014` fails locally for that reason.

## Validation results

Every Bash suite passes except `test-0000151-req-014`, as noted above. The PowerShell suites pass under `pwsh` 7.6. The security review found nothing above low.

## Skipped phases

None.
