# Changelog (0000169-release-hygiene, 25 Oct 2026)

**Feature:** release-hygiene
**Version:** 0.14.0
**PR:** pending

## What changed

PR descriptions now face the same attribution ban as commits, and release tags land on `main` after the merge. The release adds no dependency.

- req-001: `standard-boot.md`, `commit-standards.md`, and the ship skill ban AI attribution in PR descriptions. They name the host lines to leave out.
- req-002: the new `ravintio-zero/scripts/check-attribution.mjs` exits 1 on an attribution line and never prints the input. The `commit-msg` hook also rejects the `Generated with [Claude Code]` and `Claude-Session:` lines.
- req-003: ship runs the check on the PR body before `gh pr create`. The CI `validate-branch` job runs it on the PR description.
- req-004: setup sets the Claude Code `attribution` setting to empty `commit` and `pr` strings when the key is absent.
- req-005: the new `ravintio-zero/scripts/release-tag.mjs` tags `HEAD` with the product version and skips a tag that exists.
- req-006: a `release-tag` CI job runs on a push to `main` or `master`. Ship no longer creates a tag before the merge.

## Upgrade note

Setup copies the CI workflow only when `.github/workflows/ravintio.yml` is absent. A consumer with the file must copy the new `push` trigger, the job guards, the attribution step, and the `release-tag` job from `ravintio-zero/hooks/ravintio.yml` by hand. Until then, nothing tags a release on `main` in that repo.

## Why

The host asked the agent to add attribution lines, and nothing checked a PR body. Ship also tagged a commit that a squash merge leaves off `main`.
