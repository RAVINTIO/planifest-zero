# Changelog (0000205-initiative-skill, 27 Oct 2026)

**Feature:** initiative skill
**Version:** 0.27.0
**PR:** pending, updated at Step 9

## What changed

- A new `ravintio-initiative` skill coordinates an initiative in the human's session. It owns I-A Chart, I-B Activate, and I-E Delivery. It starts the driver and a watch monitor, reports progress at least every 5 minutes, at each phase end, and on request, and queues new backlog entries in `plan/.initiative-queue/` while a step runs. It never runs or resumes a step.
- The orchestrator never resumes an initiative. It resumes a step only in a step session, which has `RAVINTIO_INITIATIVE_STEP=1` or the prompt `Run initiative step {n}`. Any other session with an active initiative loads the initiative skill.
- The initiative skill writes `plan/.initiative-ack` and a step session writes `plan/.orchestrator-ack`. The strict-mode hook accepts either. The auto-trigger hook loads the initiative skill for initiative work and the orchestrator for feature work.
- A new read-only script, `initiative-watch.mjs`, prints one line per build log event and per commit, a stale-log line after 15 minutes, and a heartbeat every 5 minutes.
- The driver stops on a `Blocked:` line in the newest archived build log. It reads `position` from the initiative branch ref, so it advances only after the merge. It sets `CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS=0` unless the parent set it, and it sets `RAVINTIO_INITIATIVE_STEP=1`. It prints one `I-E Delivery:` line per step, and a `Pending:` line when every step has merged and delivery remains.
- The roadmap standards and project operations hold the table of the three parts and the seven-step run sequence. The skills catalogue, `component.yml`, the architecture overview, and the pipeline reference name the skill and count 16 skills.

## Why

Nothing coordinated an initiative from start to finish. The human's session had no role, strict mode warned it, a resume could run one step twice, and the driver missed a block, advanced early, and lost step subagents. Backlog entry 0000182 asked for the skill and the driver fixes.

## Deviations

- Adding a skill raised the skill text budget from 1598 to 1720 lines and the skill count from 15 to 16. Tests 0000031 (two suites), 0000160, 0000203, and 0000204 state the new values.
- The orchestrator `SKILL.md` size cap in test 0000151 req-011 rose from 27,700 to 27,800 bytes for the resume split.
- Tests 0000043 req-005 and req-009, 0000185 req-001, and 0000189 req-008 now describe the new owners. Test 0000151 req-013 ignores the two new child variables.
- The driver ends with `I-E Delivery: Pending:` when every step has merged. The ship skill keeps its fallback, so a driver from before this change still delivers in the last step session.
- The installed copies under `.claude/skills/` keep the old skills until step 13 of initiative 0000195 reruns setup. `test-0000151-req-014` fails locally for that reason.
- The driver that runs this initiative started before this step, so it keeps the old checks until restarted.
